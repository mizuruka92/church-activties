# data/

This folder holds **no committed data files** in the sense of table data, with one exception: the mock source
documents in `documents/` (see below).

The synthetic dataset is produced by `scripts/generate_mock_data.py` and is committed once, as SQL:

* `sql/03_load_reference_data.sql` (schema `MASTER_DATA`)
* `sql/04a_load_mass_history.sql` to `sql/04g_load_forecast.sql` (schema `DATA_OPERASIONAL`), one file per business area

Keeping a second copy of the same rows as CSV would only create two files that can disagree, so CSV
is an optional export:

```bash
python scripts/generate_mock_data.py --csv-dir data/generated
```

This writes one `SCHEMA.TABLE.csv` file per table into `data/generated/`, which Git ignores. Use it to
inspect the data in a spreadsheet or, if you prefer, to load a table through the Snowsight upload
wizard. The normal setup does not need CSV files, stages or any other cloud service.

Every value is fictional and reproducible (fixed seed and snapshot date, see
`scripts/mockdata/config.py`). Do not place real parishioner data or real operational records in this
folder or anywhere in this repository.

## documents/

`documents/laporan_kegiatan/` holds **132 mock PDF post-event reports**, one for every row of
`DATA_OPERASIONAL.LAPORAN_KEGIATAN`, written as if the table rows had been extracted from them. They are generated by the same
command as the SQL (`python scripts/generate_mock_data.py`), checked by `--check`, and described in
[docs/DOCUMENTS.md](../docs/DOCUMENTS.md). They are fictional and are not loaded into Snowflake by any step of the setup.

The public service guides are PDFs too, but they belong to the dashboard and live in `app/public_documents/` (see [docs/DOCUMENTS.md](../docs/DOCUMENTS.md)).
